# bin — Context for AI Agent

`~/.dotfiles/bin/`. Added to `$PATH`. Standalone CLIs/wrappers used both interactively and by scripts/timers.

## Output writer / decorator

`logrun` — wraps a command to tee its combined stdout/stderr into a timestamped log file (ANSI stripped) AND pipe the live stream through a decorator (`spacer` → visual break on output pauses, then `watchlog` → "idle for Ns" indicator; both fall back to `cat` if not installed).

Flags: `--name`, `--log-dir`, `--log-path`, `--decorator`/`--no-decorator`, `--fail-suffix` (default `FAILED.txt`; empty disables rename), `-c`/`--command` (run via `bash -c`), `--auto`, `--no-zshrc`.

`--auto` keeps logrun's chrome invisible until a threshold trips:

- No startup `Log:` banner. The decorator is `bin/logrun-decorator`: pure passthrough until a marker file (touched by the awk side-branch on threshold trip) appears, then prints spacer-style breaks at output pauses + an `idle Ns` indicator on stderr. Short `--auto` runs feel like a bare cmd; long ones get the visual aids. The strip-ansi + line-count + alt-screen-detect awk filter sits inside the `tee >(…)` side-branch (NOT on the foreground side, where gawk's block-buffered stdin would delay the first line of `cmd1; sleep N; cmd2` until the sleep ends).
- **awk binary preference (`--auto`)**: gawk first, then mawk + `-W interactive`, then plain `awk`. Two distinct buffering bugs force the choice. (1) Without line-buffered input, threshold detection would be deferred until enough bytes accumulated — `echo a; echo b; sleep 3; echo done` (LOGRUN_AUTO_LINES=2) wouldn't trip until the post-sleep `done` arrived. (2) mawk's `-W interactive` mode caps a single record at ~8KB and silently truncates anything longer, which dropped the on-disk log for tools like `uvx`/`rich`/`textual` that emit 20+KB tables as a single un-LF'd record. gawk is line-buffered on pipes by default and has no record-size cap, so it's strictly better here. Installed via `home.packages` in `home-manager.configsymlink/home.nix`.
- The foreground stream is plain `cmd | tee /dev/fd/4 | cat`, with the side awk attached to fd 4 — so the user sees output the instant the inner shell flushes it.
- On either `≥LOGRUN_AUTO_SECONDS` (default 10s, wall-clock) or `≥LOGRUN_AUTO_LINES` (default 100) the parent prints `Log: <path>` to stderr exactly once. Threshold marker is a side-channel file (`/tmp/logrun-lines.*`), checked synchronously after the pipeline returns to bypass bash's async signal-trap timing.
- **Threshold gates everything**: under-threshold runs are erased regardless of exit code — a fast failure looks identical to a bare command (the user gets the command's own stderr; rerun without `--auto` to keep a log). This was the original contract before a brief detour where failures always revealed; the detour surfaced log paths for any quick-failing CLI (`cr`, typoed flags, etc.) which defeated `--auto`'s "invisible until needed" goal.
- Above-threshold + exit≠0: log is renamed to `*.FAILED.txt` and a `Log renamed: …` line is printed after the in-run `Log: …` banner so the user lands on the correct path.
- Alt-screen detection: if the awk filter saw `\x1b[?1049h` AND the resolved command name isn't in `LOGRUN_TUI_SKIPLIST`, logrun emits one `logrun: '<cmd>' looks like a TUI (alt-screen detected); add to LOGRUN_TUI_SKIPLIST` line on exit. The escape bytes are stripped from the log either way.
- **PTY layer for color** (all paths in `--auto`): the inner command is wrapped in `script -qefc` so its stdout is a real PTY. Color-aware tools (`eza`, `ls --color=auto`, `git`, `grep --color=auto`) see `isatty(stdout) == true` and emit color + multi-column layout, which logrun ferries through tee to the user's terminal. Falls back to bare exec when `script` (util-linux) is missing — color is lost but everything else works. The PTY's canonical mode adds `\r` before `\n`; the side awk strips it from the on-disk log. Original command name is captured before both the PTY rewrite and the private function-timing prologue so log filenames stay readable (e.g. `log-echo-hi-...txt`, not `log-script-qefc-zsh-ic-...`).
- **In-line `\r` redraws collapsed** (both `--auto` awk filter and the non-auto `sed` branch): progress spinners that rewrite the same line with `\r` and only emit `\n` at the very end (`uv`/`uvx`, `pip`, `cargo`, `docker pull`, …) used to land in the log as one giant concatenated line of every frame. After stripping the trailing PTY-canonical `\r`, the filter applies `s/.*\r//` to drop everything before the last in-line `\r`, keeping just the final frame the user actually saw. This is NOT alt-screen TUI handling (those would still go through `LOGRUN_TUI_SKIPLIST`) — these commands print a normal table at the end and want a normal log; only the spinner noise needs collapsing.
- **fd 4 isolation** (`--auto`): the inner command is invoked with `4>&-` so the awk side-channel fd doesn't leak into descendants. Without this, `zsh -ic` helpers (gitstatus daemon, zsh-async workers) inherit fd 4 and — once reparented to systemd — keep the awk pipe writer alive past the user's command, so `wait $awk_pid` idles for several seconds. tee's own fd 4 (`tee /dev/fd/4`) is unaffected because the redirection only applies to `"$@"`.
- **Wallclock timer detached stdio** (`--auto`): the timer subshell starts with `exec </dev/null >/dev/null 2>&1` so its `sleep $auto_seconds` child can't hold the parent's stdio. `kill $auto_timer_pid` only signals the bash subshell, not the inner sleep — without the redirection, the orphaned sleep blocks any downstream pipe reader (e.g. `logrun … | cat`) for the full `$auto_seconds` even after a fast command finished.

`--no-zshrc` (paired with positional argv) makes logrun exec the command directly instead of via `zsh -ic`. The widget passes this for resolved external binaries to avoid ~800ms of zshrc replay per prompt. Aliases/functions wouldn't survive a fresh process anyway, so omitting `zsh -ic` is harmless for that case. In `--auto` mode the command is still wrapped in `script -qefc` (see "PTY layer for color" above).

Log path resolution (first match wins):

1. `--log-path PATH` flag or `log_path` env var → exact file path; skips name/dir derivation. Lets nested recipes inherit a parent's path.
2. `--log-dir DIR` flag → directory only; filename auto-derived as `log-<sanitized-cmd>-<YYYY-MM-DD-HH-MM-SS>.txt`.
3. `$build_dir` env var, if set and is an existing dir.
4. `./build/` if it exists in cwd.
5. `/tmp/` (last-resort fallback).

Filename sanitisation in cases 2-5: spaces, slashes, pipes, semicolons, etc. → `-`; truncated to 200 bytes (ext4/xfs filename limit is 255). On non-zero exit (and non-empty `--fail-suffix`, default `FAILED.txt`), the `.txt` is renamed to `.FAILED.txt`.

Other env: `LOGRUN_DECORATOR` overrides the decorator pipeline; `LOGRUN_AUTO_SECONDS` / `LOGRUN_AUTO_LINES` tune the `--auto` thresholds; `LOGRUN_TUI_SKIPLIST` (defined in `home-manager.configsymlink/home.nix` so it tracks installed TUI packages) suppresses the alt-screen hint for known-OK commands.

The accept-line widget at `zsh/zz-logrun-auto.zsh` is the user-facing entry point — it auto-wraps interactive prompt commands in `logrun --auto`. See `zsh/AGENTS.md` for widget details.

For listed-function tuning, the widget sets private `$LOGRUN_AUTO_TIMING_FILE` only on `-c` calls. The widget allocates the file with `mktemp`, so logrun's initial `in_cmd_seconds` write uses zsh's `>|` force-clobber redirection: interactive zshrc enables `NO_CLOBBER`, and plain `>` would reject the already-existing file. Logrun then appends `revealed` and `exit_code` after disposition. The parent widget compares that child-only duration with total prompt-command time; this side channel is internal, and missing or failed records produce no advice.

Companion `bin/logrun-auto-function {add|remove} NAME` applies the exact persistent command printed and copied by tuning advice. `add` ensures the additive file contains the name and clears any exclusion; `remove` records an exclusion, which can disable names seeded in `$LOGRUN_AUTO_FUNCTIONS` without editing shell code.

Companion `bin/logrun-nolog` opts out of logging from inside the wrapped command. Call it at the start of a recipe/script that should never be logged (e.g. interactive commands requiring stdin like `mwinit -o`). logrun checks `$LOGRUN_NOLOG_FILE` (a side-channel marker file, same pattern as the move handshake) after the command exits — if non-empty, the log is deleted unconditionally regardless of exit code or threshold state. Safe to call unconditionally (no-op outside logrun).

Companion `bin/logrun-move NEW_DIR` relocates the active logrun log to a different directory mid-run (preserves the filename); only works when invoked as a descendant of `logrun` since it talks to the wrapper via `$LOGRUN_PID` / `$LOGRUN_MOVE_FILE`.

Companion `bin/logrun-decorator` (Python stdlib only) is the `--auto` decorator: stays as plain `cat` until `--activate-when-exists <marker>` becomes truthy (or it receives `SIGUSR2`), then emits spacer-style horizontal lines at output pauses + an `idle Ns` stderr indicator. logrun's awk filter touches the marker synchronously when the threshold trips so the decorator activates mid-run (relying on bash's USR2 trap would defer activation until after the pipeline ends).

Test harness: `bin/test_logrun.sh` (naming, ANSI strip, fail-suffix rename, env inheritance, sanitisation, custom decorator, usage errors, `--auto` thresholds + invisibility + reveal + FAILED rename + alt-screen hint, `--no-zshrc` fast path, and private function-timing metadata).

## Commit message generator

`commit-msg` — provider chain: claude (`--print --tools "" --no-session-persistence`, skipped when `$CLAUDECODE` is set so a `claude` session never spawns a child claude) → kiro-cli (`--agent no-mcp`, stdin piping) → ollama + qwen2.5-coder:3b fallback (5s health check, started on demand) → capped file-list final fallback (first 3 files + `and N more`, 200-char hard cap; includes deleted files). jj-first / git-fallback. `VERBOSE=1` enables detailed output.

**PATH dependency (matters when invoked from the `sync-repos` schedule, not an interactive shell).** claude and kiro-cli live in `~/.toolbox/bin`, which interactive shells prepend but the systemd user manager's PATH (a login-time snapshot) and cron's default PATH do not. `dotfiles.schedule.pathExtra` therefore puts `~/.toolbox/bin` on the job PATH for both backends — without it `command -v claude`/`kiro-cli` miss and the whole chain silently degrades to the file-list fallback (the `Change <files>` commit messages). Don't rely on the `~/.local/bin` kiro-cli shim: toolbox pins it to a version path (e.g. `…/kiro-cli/2.7.1/…`) it deletes on the next auto-update, leaving a dangling symlink — that exact breakage is why `~/.toolbox/bin` (version-stable, dispatches via `toolbox-exec`) is listed first.

For jj merge commits (`parents.len() > 1`) the prompt is augmented per-parent: compute `unique_revset = (::P ~ ::others) ~ ::(merges() & (::P ~ ::others) ~ P)` (linear run on P's side since the previous merge), take the cumulative diff from `roots(unique_revset)-` (parent of the oldest unique commit = previous merge on that side) to P via `jj diff --from START --to P --git`. If that side diff is ≤ `MAX_MERGE_DIFF_LINES` (default 500, env-overridable) it goes into the prompt; else fall back to a per-commit description list. This gives the LLM code-level context for merges instead of commit-subject boilerplate.

## TTS dispatcher and backends

- **`say`** — routes by content language. Hangul (U+AC00–U+D7A3) → `say-ko`, otherwise → `say-en`. Spanish must call `say-es` directly because unmarked Latin-script text cannot be classified reliably as English or Spanish. Accepts text as args or stdin. **Preempts** still-playing audio: spawns the backend under `setsid` (PID==PGID), records the PGID at `${SAY_STATE_FILE:-${XDG_RUNTIME_DIR:-/tmp}/say.pgid}`, and `TERM`s the previous PGID on the next call. A `TERM`/`INT`/`HUP` trap forwards to the backend session so external preemption (e.g. by `mcp-tts`) tears down the whole audio pipeline instead of orphaning aplay. Bypass with `SAY_NO_PREEMPT=1`. **Auto-mute during meetings**: `say` queries `pw-dump | jq` for any `Stream/Input/Audio` whose `application.process.binary` or `application.name` matches `$SAY_MEETING_APP_REGEX` (default `zoom|teams|meet|webex|slack|chime|discord`) and silently no-ops if found (drains stdin to avoid SIGPIPE in callers). Zoom keeps its capture stream live even with in-app mute (its mute is drop-on-send, not capture-side cork), so this fires whether or not you're muted in the call. Bypass with `SAY_NO_MEETING_CHECK=1`; auto-skipped on hosts where `pw-dump`/`jq` aren't on PATH. Test: `bash bin/test_say_preempt.sh`.
- **Common backend CLI** — `say-en`, `say-ko`, and `say-es` accept `--voice N` (one-based exact pool entry), `--speed PERCENT` (`25`, `+25%`, or `-10%`), `--list-voices`, and text as arguments or stdin. Omit `--voice` for the existing deterministic caller-key selection. A CLI voice number takes precedence over the backend-specific model/voice environment override. For Edge TTS, CLI speed takes precedence over `$EDGE_TTS_RATE`; when `say-en` falls back to Piper, the resolved percentage is converted to inverse `--length-scale` so positive percentages remain faster. Options precede text; use `--` when text itself begins with `-`.
- **`say-en`** — edge-tts primary, Piper offline fallback. The numbered Edge pool is `en-GB-SoniaNeural`, `en-US-AvaMultilingualNeural`, `en-US-AndrewMultilingualNeural`, `en-GB-LibbyNeural`, `en-US-BrianMultilingualNeural`; each slot maps to its former Piper entry (`alba`, `amy`, `ryan`, `cori`, `lessac`) for fallback. Edge uses normal rate by default. If Edge synthesis fails, only the selected Piper model is downloaded on demand; a failed download falls back to alba. `$EDGE_TTS_VOICE` overrides automatic Edge selection. Setting `$PIPER_MODEL` without `--voice` preserves the explicit Piper-only path and bypasses Edge.
- **`say-ko`** — edge-tts (requires internet). Pool: `ko-KR-SunHiNeural`, `ko-KR-InJoonNeural`, `ko-KR-HyunsuMultilingualNeural`. Default rate `+50%`; `$EDGE_TTS_RATE` and `$EDGE_TTS_VOICE` override automatic defaults.
- **`say-es`** — edge-tts (requires internet). Seven numbered Spain/Mexico/US Spanish voices: `es-ES-AlvaroNeural`, `es-ES-ElviraNeural`, `es-ES-XimenaNeural`, `es-MX-DaliaNeural`, `es-MX-JorgeNeural`, `es-US-AlonsoNeural`, `es-US-PalomaNeural`. It otherwise matches `say-ko`, including the `+50%` default and Edge environment overrides.
- **`say-voice.sh`** — the _single place_ the common backend CLI and caller→voice mapping live (sourced by `say`, `say-en`, `say-ko`, `say-es`; never run directly). With no explicit voice number, `say_pick_index <poolsize>` returns `sha256(key) mod poolsize` — **sha256, not `cksum`/CRC32**: CRC32 is linear over GF(2) and clusters structured keys (sequential PIDs, prefix-sharing session ids), whereas sha256 stays uniform for whatever opaque key the caller passes, and the caller needs no knowledge of the pool size. Deterministic and stateless, so a given key always maps to the same voice.
  - **Key contract** (`say_resolve_key`): `$SAY_VOICE_KEY` is an opaque, arbitrary identity string. **Unset** → fall back to `$PPID` (stable for interactive/direct callers; only an orphan `PPID==1` stays unidentified). **Set but empty** → the caller has no identity → **unidentified** → the pool’s first entry (SunHi / Sonia with alba fallback / Alvaro). Any non-empty value (including `"1"`) is honoured verbatim and hashed; it is distinct from `--voice 1`.
  - **Why detaching callers pass an explicit key**: a backgrounded `setsid` child does **not** get `PPID==1` on hosts with a user-systemd subreaper — it reparents to the reaper's pid (or keeps a racy short-lived parent pid). Neither is the semantic caller, so relying on the `$PPID` fallback there would give an unstable voice. So: `claude-stop-tts` / `claude-notification-tts` pass the Claude `session_id` (stable per session; empty → default voice), `mcp-tts` passes its server `$$` (stable per server lifetime). `say` itself resolves the key from _its own_ `$PPID` and exports `SAY_VOICE_KEY` before its `setsid`, so a directly-invoked `say "…"` keys off the caller shell. `kiro-response` `exec`s `say-ko` directly, so the backend's `$PPID` fallback covers it with no change. Test: `bash bin/test_say_voice.sh` (silent playback stubs; selection/options/propagation).

## Claude Code hooks

- **`claude-stop-tts`** — Stop hook. Reads `last_assistant_message` from the Stop hook stdin JSON (authoritative current-turn text; the `transcript_path` file lags Stop firing by several seconds and would replay the _previous_ turn). Picks the last paragraph starting with `요약:`, strips that prefix so TTS speaks only the summary content (the user doesn't want "summary" announced every turn), strips markdown, caps to `$CLAUDE_TTS_MAX_CHARS` (default 500), and pipes to `say` (which routes by language). Falls back to the last non-empty paragraph when no `요약` marker exists, and falls back to parsing `transcript_path` if `last_assistant_message` is missing (older Claude Code). Spawns via `setsid` so audio outlives the turn. Debug log at `~/.local/state/claude-stop-tts.log` (override via `$CLAUDE_TTS_LOG`; auto-trimmed to 1000 lines when over 2000). Wired into `~/.claude/settings.json` `hooks.Stop`.
- **`claude-notification-tts`** — Notification hook. Fires when Claude Code asks for permission to use a tool, or when the prompt has been idle. Reads `.message` from the hook's stdin JSON, classifies on `permission/idle/other` substring match, and speaks via `say`. Permission asks → `"도구 실행합니다. <tool> 사용 권한을 요청합니다."` (extracts the tool name from the standard message). Idle → `"입력을 기다리고 있습니다."` Replaces the previous flow where the assistant manually called `say_ko` before each tool call (it forgot, the hook never forgets). Returns `{"continue": true, "suppressOutput": true}` so the transcript stays clean. Debug log at `~/.local/state/claude-notification-tts.log` (override via `$CLAUDE_NOTIFY_TTS_LOG`; auto-trimmed). Wired into `~/.claude/settings.json` `hooks.Notification`.

## VPN supervisor

`vpn-up` + `vpn-watch` — generic openconnect-VPN supervision.

**Why**: openconnect installs DNS + routes pointing at the VPN concentrator. If the underlying network changes (Wi-Fi roam home → café → office) without first tearing down the tunnel, the box ends up with a dead tunnel that still claims to be the default route — every DNS lookup hangs and the network is effectively inaccessible until the user notices.

`vpn-up` bundles two things into one foreground command: (1) `vpn-watch` spawned in the background, (2) the configurable VPN start command (`vpn-up CMD ARGS…` or `$VPN_START_CMD`). When the start command exits, the watcher is reaped via EXIT trap. The VPN client itself is expected to prime sudo (do `sudo /bin/true` then `sudo openconnect …`); the watcher reuses that cache for its later `sudo -n pkill` and keeps it warm via background `sudo -nv` every `$VPN_SUDO_REFRESH` seconds (default 240).

`vpn-watch` monitors `org.freedesktop.NetworkManager` `Connectivity` via `gdbus`; transitions out of `FULL` (4) trigger a `$VPN_DEBOUNCE_SEC` (default 5) wait, and if connectivity is still lost, `sudo -n pkill -TERM <process>` (or `kill -TERM <PID>` when `VPN_PROCESS_PID` is set).

Public repo stays VPN-flavour-agnostic; site-specific glue (the actual VPN binary name) lives in a sibling repo's `vpn.zsh`.

Env: `VPN_PROCESS_NAME` (default `openconnect`), `VPN_PROCESS_PID` (preferred when known — name-based watch is fine for openconnect since it's a singleton in practice), `VPN_DEBOUNCE_SEC`, `VPN_SUDO_REFRESH`, `VPN_STARTUP_WAIT` (default 30).

No NOPASSWD sudoers entry needed: one prompt per VPN session (the client's own), watcher inherits the cache.

## Zellij session cycler

`zellij-cycle` — wraps `zellij attach --create` in a loop. On detach, cycles to the next active session. Supports session names with spaces. Numeric argument (e.g. `1`, `2`) attaches to the Nth existing session instead of a named one. Xmonad scratchpads now launch `zmx-select` instead (see `xwindow/AGENTS.md`).

## zmx session picker

`zmx-select` — fzf picker over zmx sessions, aliased to `z` (`zsh/utility.zsh`). It shows the sorted union of running sessions and stopped sessions with saved snapshots; there is no preset-name file or automatic `main` fallback. With no entries, the empty picker remains available for creating a typed name.

Enter attaches. For a stopped saved session, it stages the persisted output, prints the last `${ZMX_RESTORE_LINES:-50}` lines before the first prompt, changes to the persisted cwd when that directory still exists, and starts a replacement login shell. Missing cwd metadata leaves the shell in the selector's current directory. Other typed names are created on demand by `zmx attach`. After detaching from a still-running session, `Ctrl-\` in the picker attaches to the previously attached running session; each switch swaps the remembered pair, so repeatedly detaching and pressing `Ctrl-\` alternates between the last two sessions. Before a previous session exists, `Ctrl-\` reattaches the latest session instead of exiting. When the selector has no last session yet, `Ctrl-\` is unbound and does nothing. Esc also reattaches the session just detached from without changing the pair, while Esc on the initial picker exits. Compact status emoji follow the activity marker and can combine: `🥇` most recent, `🥈` previous, and `🔗` attached. The picker header includes the same legend. `Ctrl-N` forces a new session with the typed name, adding `-2`, `-3`, and so on if the name is taken. `Ctrl-D` forgets the highlighted stopped session and its snapshot metadata. It ignores running sessions and exits instead of creating a replacement when it removes the final entry. `Ctrl-/` cycles through horizontal (`right:60%:follow`), vertical (`down,50%`), and hidden preview layouts, matching `_gh`. `Ctrl-C` always exits.

The preview shows the session's last 500 `scrollback` lines and then streams live output (`zmx history … | tail`, then `exec zmx tail`). Stopped sessions fall back to the last `zmx-history` snapshot when one exists. The picker passes `--no-mouse` so ordinary dragging selects preview text and Ghostty's default `copy-on-select` copies it. This intentionally disables fzf clicks and wheel scrolling; keyboard navigation and `Shift-Up`/`Shift-Down` preview scrolling remain available.

`zmx-history` — long-running snapshot daemon started by the Home Manager `zmx-history.service`. zmx's own `<session>.log` is only internal diagnostics, while actual scrollback lives in the session process, so the daemon persists rendered `zmx history` output and cwd metadata under `${ZMX_HISTORY_DIR:-${XDG_STATE_HOME:-~/.local/state}/zmx/history}`. It snapshots all sessions at startup, then polls every `$ZMX_HISTORY_SCAN_SECONDS` (default 5s), discovers sessions from zmx's reported socket directory without connecting to them, and uses each session's cheap diagnostic-log `(mtime,size)` signature as an activity signal. Daemon captures resolve cwd through the session pid in `zmx list`; `zsh/zmx-history.zsh` also calls `zmx-history snapshot <session> "$PWD"` synchronously from `zshexit`, before the socket disappears, so a normal zsh exit includes final output and the exact final directory. All captures and removals share `.snapshot.lock`, preventing an older concurrent daemon capture from overwriting the final snapshot and serializing deletion with in-flight captures. Snapshots are capped at `$ZMX_HISTORY_MAX_BYTES` (default 5 MiB), staged in `$XDG_RUNTIME_DIR`, compared with `cmp`, and replaced only when rendered history changed; cwd metadata is updated independently, so a `cd` does not rewrite unchanged scrollback. Temporary files are flushed before rename and the containing directory is synced afterward. The state directory is mode `0700` and snapshot/name/cwd files are `0600`. Thus idle sessions produce no persistent scrollback writes, a forced reboot loses at most one scan interval, a normal zsh exit captures final state, and an interrupted write leaves the prior complete snapshot. Companion CLI actions `snapshot` / `path` / `cwd` / `has` / `show` / `remove` / `list` are used by the hook and `zmx-select`; `list --with-cwd` supplies all saved cwd metadata to the picker in one process. `remove` deletes the snapshot and both metadata files, and hashed filename suffixes avoid collisions after sanitising session names. Test: `bash bin/test_zmx_history.sh`.

Each row is `name activity [status]  <cwd>`. Session names are bold. When a name contains the literal `help`, that substring is dim while the other characters stay bold; status and cwd text remain normal. The fixed one-cell activity column uses a bold bright-orange `●` for a foreground job, green `❯` when the shell owns the terminal and is on a prompt, and a dim gray `·` for a stopped saved session. It stays blank when `/proc` cannot be parsed. Running state comes from `/proc/<pid>/stat`: a foreground terminal process group different from the session shell's process group means a job is active. This also catches external commands launched inside shell functions, but a long-running builtin that never creates a job remains indistinguishable from the shell itself. Padding accounts for UTF-8 byte widths and double-width status emoji so cwd columns stay aligned. A stopped row appears only when a persisted snapshot exists and shows its persisted cwd when available. For running sessions the directory is the shell's **live** cwd read from `/proc/<pid>/cwd` and `$HOME`-shortened to `~` — `zmx list` only reports `start_dir`, which stays at the creation directory no matter how much you `cd` (verified: a session `cd`'d to `/tmp` still lists `start_dir=~/.dotfiles`). The live column is left blank when `/proc` can't answer; a stale directory would be worse than none. `🔗` marks sessions with a terminal-side `zmx attach` client. The selector finds each persistent server from the session shell's parent PID and excludes it, and ignores `zmx tail` preview clients; `zmx list`'s client count cannot distinguish those processes. The process ID isn't displayed; it is used only to resolve the cwd, infer activity, and identify the persistent server.

The picker writes the window title itself: `zmx` while the list is up, `[<session>]` right before `attach`. It sets the UTF-8 `_ZMX_SESSION` property on Ghostty's exported `$WINDOWID` before attaching. Before the first attachment it removes any stale property; after a detach it retains `last_session`, so XMonad renders `[<previous>] zmx` while the picker is open. XMonad treats that property as the stable session identity and prepends it to the mutable OSC title, so a foreground TUI cannot hide the session name by emitting OSC 0/2. The session's shell still re-emits its richer OSC title at its next prompt. Title writes go to `/dev/tty`, never stdout, and property writes are best-effort so the picker still works outside X11.

`Ctrl-\` is zmx's own per-client detach binding. It returns to the picker because the loop below resumes when `attach` exits. `zmx detach` is deliberately NOT wired to anything because it drops *every* client of the session. A CLI-side per-client detach is impossible in principle: all clients mirror one PTY, so code running inside the session cannot tell which window's keystrokes it is serving. Only the client, which reads your terminal, knows.

The picker **loops**: after `zmx attach` returns because of `Ctrl-\` or the session's shell exiting, it rebuilds the list and reopens. The title still identifies `last_session`, and the cursor returns to that row via `--bind "load:pos(N)"` (N is the row index from the parallel `$order` array). The `load` event is required because `start` can fire before piped rows arrive and silently discard `pos`; cursor restoration applies when the session still exists in the rebuilt running/saved union. `attach` is therefore not `exec`'d. If the session still exists when `attach` returns, the picker records that return as a detach and Esc reattaches it. `previous_session` tracks the prior distinct attachment, and selecting it with picker-level `Ctrl-\` swaps it with `last_session`. When that target is absent, `Ctrl-\` falls back to the running `detached_session`; stopped snapshots are never resurrected by the shortcut. Running cwd values are cached by session process ID. Unchanged sessions reuse the cache, while the detached session and sessions with new process IDs are refreshed. `list --with-cwd` loads all saved cwd values at once. This avoids the old per-row helper processes before `fzf` starts accepting keys. If the shell exited and removed the current session, Esc exits normally. `Ctrl-C` always exits with status 130.

New sessions are created as `zmx attach <name> zsh -l`, matching ghostty's `command = zsh -l`. Saved sessions are recreated through `bin/zmx-restore`, which replays the staged tail and changes directory before `exec zsh -l`; the staging avoids a race with the new session's first daemon snapshot. Without an explicit command zmx spawns a login `$SHELL`, which is bash on this account (LDAP, no `chsh`) — verified: a bare `zmx attach` session runs `-bash`, with the command it runs `zsh -l`. The command only applies at creation; sessions already running bash keep bash until they're killed.

Beware `zmx attach --help`: zmx takes it as a session name and attaches to a session called `--help` rather than printing usage — it looks like a hang. `zmx help` is the usage command.

## Notify-webhook dispatcher

`notify-webhook` — dispatcher for structured alerts. Flags: `-d DESTINATION`, `-t TITLE`, `-p {low|normal|high|urgent}`, `-u URL`. `-d` exports the validated name as `$NOTIFY_DESTINATION`; backends map it to private configuration. Backends live in `~/.dotfiles/script/logger/backends/<name>.sh` and must define `notify_send TITLE PRIORITY URL MESSAGE`. Selection priority: explicit `$NOTIFY_BACKEND` environment variable → auto-detect (`telegram.env` present → `telegram`) → `none`. The unconfigured default and unknown backends remain silent no-ops, so machines without notification configuration do not fail. An explicitly requested Telegram destination fails when missing or incomplete. Test: `bash bin/test_notify_webhook.sh`. See `script/logger/AGENTS.md` for backend details.

## Dropbox Downloader

`dropbox-get [--all] [--to DIR] [QUERY]` — one-way personal Dropbox downloader backed by `rclone` and `fzf`. The first run creates an rclone remote named `dropbox` and opens Dropbox's one-time browser authorization. The OAuth token remains mutable machine state at `~/.config/rclone/rclone.conf`, outside Home Manager and git. Config command output is suppressed so the token cannot reach the terminal or logs. Subsequent runs list remote file paths without downloading content, fuzzy-search only the path column, and preserve selected paths under `~/Downloads/Dropbox` by default. Tab multi-selects and Ctrl-A selects all current matches. `--all` performs an explicit full one-way `rclone copy`; neither mode deletes local files or uploads workstation files. `DROPBOX_REMOTE` and `DROPBOX_DOWNLOAD_DIR` override the defaults.

The picker is in `LOGRUN_TUI_SKIPLIST` so the shell runs it directly and personal paths do not enter `logrun`. Use `fd PATTERN ~/Downloads/Dropbox` for local filename search and `rg PATTERN ~/Downloads/Dropbox` for content search after download. Dropbox is only for personal/public files; Amazon data must not be downloaded to or uploaded through the personal account. Test: `bash bin/test_dropbox_get.sh`.

## logrun config files (cross-machine, in this dir)

- `logrun-auto-functions` — committed additive function list, read with an mtime cache on each prompt. `.gitattributes` maps it to `merge=union-dedupe` so concurrent additions auto-merge.
- `logrun-auto-functions-disabled` — committed exclusion list that overrides both the additive file and `$LOGRUN_AUTO_FUNCTIONS`; it uses normal merging because `add` removes an existing exclusion.
- `logrun-auto-function` — management CLI used by copied advice commands; it updates the additive/exclusion files idempotently.
- `logrun-tui-skiplist` — committed list of curses-style commands `logrun --auto` saw with alt-screen escapes. The widget skips wrap for these so the TUI doesn't break under any pipe. Auto-extended by `bin/logrun` when an unknown TUI is detected. `.gitattributes` maps to `merge=union` for cross-machine merging. (The `LOGRUN_TUI_SKIPLIST` env var in `home.nix` is a separate, in-process baseline — both feed the same skip check.)

## Spell check (matches nvim)

`spellcheck-md FILE...` — spell-check prose/markdown with **codespell**, reusing nvim's built-in spell allowlist (`~/.config/nvim/spell/en.utf-8.add`) as codespell's `--ignore-words`, so results match what nvim highlights (words you `zg`-added in nvim are ignored here too). Defaults to `*.md` in cwd when no args. Runs codespell if installed, else `nix run nixpkgs#codespell`. Override the allowlist with `$SPELL_ADD`; pass extra flags via `$CODESPELL_ARGS`. Exit status is codespell's (0 = clean).

**Why codespell, not aspell:** codespell flags known typos (curated typo→fix list), not every unknown word, so digit-suffixed identifiers and API names (`EC2`, `dup2`, `time64`, `CreateFile2`) don't false-positive — aspell's `en` dictionary rejects any word ending in a digit and can't even load such an allowlist. This is the tool to reach for when asked to "spell-check like nvim does".
